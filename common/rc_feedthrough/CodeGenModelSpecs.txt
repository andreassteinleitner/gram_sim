# This file contains model specifications for the IFR Code Generation for PX4.
# It MAY be placed in a model folder to give some specifications for the model.

# Usage: 
#	All lines without a '#' contain relevant specifications for the IFR CodeGen. 
#	A '#' can be used to comment out lines and thus disable specifications.
#	A ':=:' is used to separate the specification name from the actual specification value
#	All specifications are completely optional.
# 	All specifications in this file are model-specific. Applied only to the model in its folder it is placed in. For universal settings see TEMPLATE_CodeGenSpecs.txt.
#  Model-specific specifications will usually overwrite any default specifications given for all models in the universal CodeGenSpecs.
#  Sometimes the default specifications are not overwritten. Instead they are expanded with the model's specification. If this is the case it will be noted in the description. 
#	To add or expand some specification just add a new line.
#	Further Infos about the specifications can be found in the IFR CodeGen README.

# This file contains all necessary specifications for a model to be used with the IFR Code Generation for PX4.


# -------------------------------------------
# --- CodeGen General Specifications Part ---
# -------------------------------------------
#
# These specifications define how the IFR CodeGen executes its tasks.

# Path to the directory the CodeGen uses to compile the C-Code from the Simulink-Models. The user must have full privileges for this directory. 
# This is a mandatory specification.
# It is recommended to use a top level directory on any drive (e.g. C:\IFR_CodeGen_WorkDir), as the IFRCodeGen will automatically create various subfolders for every opened model.
# It is NOT recommended to place the working directory within the WSL. Performance issues may occur.
# The user can specify a full or relative path. The latter uses "..\" to specify moving up in the file structure and is relative to the IFR CodeGen's main directory.
# Only a single "work_dir" value may be specified.
#work_dir :=: C:\IFR_CodeGen_WorkDir	# Example for an absolute path to the CodeGen working directory
#work_dir :=: ..\IFR_CodeGen_WorkDir	# Example for a relative path to the CodeGen working directory

# Flag to force the IFR CodeGen to evaluate all found UORB/Topic definitions.
# By default the IFR CodeGen will only evaluate (e.g. creating Simulink Bus Object) UORB/Topic definitions that are relevant to the opened model.
# If no such specification is given, the IFR CodeGen will stick to the default behavior.
# The only possible value to force evaluation of all UORB/Topic definitions is "true". All other values will be silently ignored.
#eval_all_uorbs :=: true

# Flag to enable an additional ordering of a model's parameters into group(s). 
# If enabled the parameter struct and also the parameter buses will get an additional level, which separates parameters by their specified parameter group(s).
# By default the IFR CodeGen will not use the parameters' group(s) within structs and buses as an ordering instrument/level.
# If no such specification is given, the IFR CodeGen will stick to the default behavior.
# The only possible value to enable an additional ordering of a model's parameters into group(s) is "true". All other values will be silently ignored.
#param_group_order :=: true

# CodeGen file (Matlab function) to define buses for a model, which has to be placed within the model's folder.
# This function will automatically be evaluated by the IFR CodeGen when opening a model or generating the code.
# A template resp. example is provided in the example models of the IFR CodeGen.
# If no file name is specified, the IFR CodeGen looks for a file named "IfrCgDefineBuses.m". If this does not exist, it is assumed that no buses should be defined. This is also a valid behavior.
# This setting is universal and will be applied to all models.
# It is also possible to specify a file located in a subfolder of the model's main directory. See example below.
# Info: If the user wants to run a script/function to define buses for ALL or MULTIPLE of his models this is NOT the correct specification. Use "execute_before" or "run_scripts_before" for this task.
# Only a single file may be specified.
#define_buses_file :=: defineBusesExample.m
#define_buses_file :=: codegen\defineBusesExample.m

# Path to directories containing UORB definitions provided by the model.
# These UORB definitions will always be evaluated and automatically added to the PX4 source code when generating the code for a module.

# The user can specify a full or relative path. The latter uses "..\" to specify moving up in the file structure and is relative to the model's main directory.
# The IFR CodeGen also looks for default folder named "ifrcg_uorb_defs" within the model's main folder. Do NOT include it with this option a second time.

# Additional UORBs/Topics which should be evaluated when opening the model.
# By default the IFR CodeGen will only evaluate UORB/Topic definitions for topics being an input or output of the model.
# This specification is for example helpful if a specific UORB constants is required, which is defined in a random UORB/Topic
# Will expand universal CodeGenSpecs.
# Info: this specification is irrelevant, if "eval_all_uorbs" is set to true (see above in general).
# Info: the UORB can be given in snake_case or PascalCase and with or without the .msg extension
# Multiple UORBs can be specified
#additional_uorbs :=: uorb_name
#additional_uorbs :=: UorbName.msg

# ----------------------------------------------------
# --- CodeGen Module Specifications Part ---
# ----------------------------------------------------
#
# These specifications are applied to all PX4 modules the IFR CodeGen works with or creates.
# They may be overwritten by module-specific specifications.

# Set name of a PX4 module created from this Simulink model.
# If no name is given it will be created automatically based on the main model's name.
# Info: the name will be converted to snake-case automatically.
# Info: if given within CodeGenSpecs.txt or CodeGenModelSpecs.txt the "prefix_module" will be added automatically.
# Only one module name may be specified.
#module_name :=: example_name

# Name of subfolder within the PX4\msg directory, which will contain model/module's own topic/UORB-definitions. 
# Directory (if given) will be used, when topic/UORB-definitions are automatically moved from a module/model directory to PX4 source code. 
# Otherwise the default PX4\msg folder for topic/UORB-definitions will be used.
# Only a single directory may be specified.
#uorb_dir :=: ifr

# Default stack size for modules created as an individual PX4 task. 
# Only one stack size may be specified.
#module_stacksize :=: 2048

# Default execution interval for CodeGen's main loop.
# This is the outer loop doing mainly UORB/topic subscriptions and publications.
# It must be given in seconds. For example a value of "0.01" means that the loop is executed every 0.01s (=100Hz)
# Only one execution interval may be specified.
#main_loop_interval :=: 0.01

# Default execution interval for model loop.
# This is the inner loop running the model's code resp. algorithm.
# It must be given in seconds. For example a value of "0.01" means that the loop is executed every 0.01s (=100Hz)
# Only one execution interval may be specified.
#model_loop_interval :=: 0.01

# --- CodeGen Naming Conventions Specifications Part ---

# These specifications change how the IFR CodeGen does its automatically naming of files, variables etc.
# If none of the specifications is given the CodeGen falls back to its default values, which are identical to the examples below.

# General Prefix for the IFR CodeGen. Will be used to distinguish automatically created variables/structs and Bus Objects in Matlab and Simulink.
# To disable the usage of the prefix specify the keyword: NO_CODEGEN_PREFIX 
# Only a single prefix may be specified.
#prefix_codegen :=: IFRCG
#prefix_codegen :=: NO_CODEGEN_PREFIX

# Prefix which is added to all created Simulink Bus Objects. 
# Only a single prefix may be specified.
#prefix_bus :=: Bus

# Prefix for model. May be used to distinguish different models by automatically adding the prefix to automatically named variables, files, busses etc.
# Only one model prefix may be specified.
prefix_model :=: Ifr_Feedthrough

# Prefix which is added to all created PX4 modules using the CodeGen to easily distinguish them. 
# Only a single prefix may be specified.
prefix_module :=: ifrcg

# Name for variable/struct and Simulink Bus Object created from given PX4 parameter definitions
# Only a single name may be specified.
#name_params :=: Params

# Name for variable/struct and Simulink Bus Object created from given constant definitions
# Only a single name may be specified.
#name_constants :=: CONSTANTS

# Name for variable/struct created from UORB/Topic definitions 
# Only a single prefix may be specified.
#name_uorb :=: Uorbs

# Prefix which is added to all created Simulink Bus Objects from UORB/Topic definitions 
# Only a single prefix may be specified.
#prefix_uorb_bus :=: Uorb

# Name for variable/struct and Simulink Bus Object created from constant definitions found in UORB/Topic definitions 
# Only a single name may be specified.
#name_uorb_constants :=: CONSTANTS_UORB
